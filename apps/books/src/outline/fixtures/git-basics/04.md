## ローカルリポジトリを作る

練習として自分のPCにGitのローカルリポジトリを作成してみます。ローカルリポジトリは次の手順で作成します。


1. フォルダを作成
2. Gitローカルリポジトリ作成コマンド（`git init`）実行

それでは、ローカルリポジトリを作成してみましょう。

:::step
1. フォルダの作成

   まずは任意の場所（デスクトップなど）に「git-text」という名前のフォルダを作成します。

   ![git-testフォルダの作成](/api/attachments.redirect?id=65feaeab-9dc6-4e19-ac4b-bcb721c5ca33)
2. VSCodeでフォルダを開く

   作成した「git-text」フォルダをドラックしてVSCodeにドロップすることでフォルダをVSCodeで開くことができます。

   ![VSCodeでgit-testを開く](/api/attachments.redirect?id=3fd45ad0-13a8-4803-9c91-892a18c3dbdd)
3. ターミナルを開く

   VSCodeをアクティブにして「`Ctrl + @`」を押すことでターミナルを開くことができます。

   ![VSCodeでターミナルを開く](/api/attachments.redirect?id=9e726149-2e95-4d6f-af69-0a3c97cf1e87)
4. Gitリポジトリを作成

   ターミナルに下記のコマンドを入力してローカルリポジトリを作成します。

   *コマンド実行*

   ```bash
   git init
   ```

   次のように「`Initialized empty Git repository in C:/Users/ユーザー名/Desktop/git-test/.git/`」と表示されればローカルリポジトリの作成が完了です。

   ![ローカルリポジトリの作成](/api/attachments.redirect?id=16a272a4-3618-4fb6-826e-13236ae242b9)

:::

これで、ローカルリポジトリが作成されました。ローカルリポジトリはフォルダ内に「`.git`」というフォルダが作成されます。このフォルダにリポジトリに関する情報が保存されます。


:::syntax ローカルリポジトリの初期化
ローカルリポジトリにしたいフォルダを作成し、次のコマンドを入力してローカルリポジトリを作成します。

```
git init
```

:::

//clearpage


:::note .gitフォルダについて
リポジトリに指定されたフォルダには「.git」というフォルダが作成されます。このフォルダは通常非表示になっているため、Windowsエクスプローラーで「隠しファイル」にチェックを入れることにより確認できます。

 ![.gitフォルダの確認](/api/attachments.redirect?id=0c359496-0938-44b5-b871-1c485a9cd259)

Gitでは基本的にこの「.git」フォルダが配置されているフォルダを「リポジトリ」として利用します。「.git」フォルダの中にはリポジトリに対する設定や、今後追加される履歴などが保存されます。

:::

## Gitの設定

Gitを使うためには、ユーザー名とメールアドレスを設定する必要があります。Gitの設定は次の手順で行います。

:::step
1. ユーザー名の設定

   VSCodeのターミナルに次のコマンドを入力してユーザー名を設定します。`<ユーザー名>`は自分の名前に置き換えてください。

   *コマンド実行*

   ```bash
   git config --global user.name "<ユーザー名>"
   ```

   ![](/api/attachments.redirect?id=6ffcd105-2881-46ec-a0d9-2ba4c8acbb7a)
2. メールアドレスの設定

   次のコマンドを入力してメールアドレスを設定します。`<メールアドレス>`は自分のメールアドレス（GitHubのアカウントに紐づけているメールアドレス）に置き換えてください。

   *コマンド実行*

   ```bash
   git config --global user.email "<メールアドレス>"
   ```

   ![](/api/attachments.redirect?id=1b33e8fd-b124-469e-bb84-48c99ce7a840)
3. 設定の確認

   次のコマンドを入力して設定内容を確認します。

   *コマンド実行*

   ```bash
   git config --list
   ```

   次のように設定内容が表示されれば設定が完了です。最初の表示で見えない場合は下キーを押せば表示されます。

   ![設定内容の確認](/api/attachments.redirect?id=2c4cf247-2304-45ef-b596-bacf6c587e11)

:::


:::syntax Gitの設定コマンド
Gitの設定は次のコマンドで行います。

```
git config --global user.name "<ユーザー名>"
git config --global user.email "<メールアドレス>"
```

設定内容を確認するには次のコマンドを入力します。

```
git config --list
```

:::

## コミット

### コミットとは

実際に開発が始まると、新しいファイルを作成したり、既存のファイルを書き換えたり、不要なファイルを削除したり、ファイル名を変更したりさまざまな編集が行われます。そうした変更にメッセージをつけてリポジトリに登録する作業を「**コミット（commit）**」といいます。

リポジトリはコミットを行う事で変更の履歴が時系列に繋がって記録されていきます。リポジトリを使う開発者はこのコミットの履歴をみることにより、いつ、誰が、どういう目的で、どのようにファイルを修正したかを把握する事ができます。

また、コミットした内容はリポジトリに保存されるため、コミットした時点のファイルの状態に戻すことができます。このようにコミットはファイルの変更履歴を管理するための重要な作業です。

### コミットする手順

Gitのローカルリポジトリが出来たので、早速ファイルを作成し、コミットしてみます。コミットの流れは下記になります。


1. ファイルの変更（追加、修正、削除など）
2. コミット対象のファイルをステージに移動（ステージング）
3. ローカルリポジトリにコミット

次の手順でコミットを行いましょう。

:::step
1. ファイルを追加

   `git-test`を開いているVSCodeで`test.txt`という名前のファイルを作成します。

   ![test.txtファイルの作成](/api/attachments.redirect?id=942e979e-8066-4986-a1d8-df9923fb20eb)
2. ファイルの編集

   `test.txt`に「はじめてのGit」という文字列を追加してください。

   ![test.txtの編集](/api/attachments.redirect?id=13daba2b-bc27-4e96-8808-a0325df10ff5)
3. リポジトリのファイル変更の確認

   VSCodeのSource Controlでリポジトリのファイル変更を確認します。

   ![VSCodeにて変更の確認](/api/attachments.redirect?id=6d63f27b-f974-4ee8-baf6-51f22f8a1b0f)

   このように、VSCodeはGitのリポジトリに変更がある場合、Source Controlで変更状況を確認することができます。
4. 追加したファイルをコミット対象にする

   Source Controlで`test.txt`の箇所にある「`+`」ボタンをクリックします。

   ![test.txtをステージに移動](/api/attachments.redirect?id=75665d63-3f56-4b8b-9c78-30970d536fb0)

   次のように「Changes」から「Staged Changes」にファイルが移動します。

   ![test.txtをステージに移動](/api/attachments.redirect?id=2bb75379-4655-4c27-990d-b1ba32654611)
5. コミットメッセージの追加

   コミットメッセージを入力します。コミットメッセージは他の開発者がコミット内容を理解しやすいように簡潔に記述します。今回は「`はじめてのコミット`」と入力して「`Commit`」ボタンを押します。

   ![コミットメッセージの入力](/api/attachments.redirect?id=2fca228d-4094-4aeb-8e37-f72b986f9ea1)
6. コミットの実行

   コミットが実行されます。コミットが完了すると「Changes」や「Staged Changes」の表示が消えます。

   ![コミット完了](/api/attachments.redirect?id=d080b948-0335-4613-9572-08539a67a0b1)
7. コミット履歴の確認

   コミットが完了したので、コミット履歴を確認します。Source Controlの下図矢印の箇所をクリックするとGit Graph（コミットの履歴）が表示されます。

   Git Graphにはコミット毎に次のような情報が表示されます。
   
   | 項目  | 内容  |
   |-----|-----|
   | Graph | コミットの履歴をグラフで表示 |
   | Description | コミットメッセージ |
   | Date | コミットした日時 |
   | Author | コミットしたユーザー |
   | Commit | コミットのハッシュ値 |

   ![コミット履歴の確認](/api/attachments.redirect?id=bd8af3d3-6249-4768-ae17-64d8330d585d)

   Git Graphをクリックするとコミットの履歴が表示されます。

   ![](/api/attachments.redirect?id=b451970f-4564-42f9-b782-6983ef116696)

:::

このように、Gitではファイルの変更をコミットすることで変更履歴を記録することができます。コミットは変更内容に対してメッセージをつけることができるため、他の開発者がコミット内容を理解しやすくなります。

//clearpage


:::syntax コマンドでコミットする
コマンドでコミットするには、次のコマンドを入力します。`<コミットメッセージ>`はコミットメッセージに置き換えてください。

```bash
git commit -m "<コミットメッセージ>"
```

:::


:::note ステージングとは
このようにファイルをコミット対象にすることを、「**ステージング**」または「**ステージに移動する**」といいます。ステージングを行うことで、コミット対象のファイルを選択することができます。

:::


:::syntax コマンドでステージングする
ファイルをステージングするには、次のコマンドを入力します。

```bash
git add <ファイル名>
```

更新した全てのファイルをステージングする場合は次のコマンドを入力します。

```bash
git add .
```

:::


:::note コミットメッセージの書き方
コミットメッセージは次のような書き方が一般的です。

*コミットメッセージの書き方*

```
<変更内容の要約>

<変更した理由や詳細>
```

例えば、次のようなコミットメッセージが一般的です。

*コミットメッセージの例*

```
README.mdの修正

タイトルの修正
```

このように、コミットメッセージは変更内容の要約と変更した理由や詳細を記述します。

:::

//clearpage

## コミット間を移動してみる

コミットは時系列で繋がりを持っています。Gitはコミット単位で内容を戻す事ができます。

### 前のコミットに戻る

それでは一つ前のコミットに戻してみます。

:::step
1. 一つ前のコミットに移動

   Source ControlでGit Graphを表示して、「初めてのコミット」を右クリックして「Checkout」を選択します。

   ![コミット履歴の確認](/api/attachments.redirect?id=bbf69754-beea-41c3-bd46-7bbaa4121efd)
2. 警告画面の確認

   警告画面が表示されます。「Always Accept」にチェックを入れて、「Yes checkout」をクリックします。

   ![警告画面](/api/attachments.redirect?id=e53eb671-a1fd-4fb1-8e85-2ae31d98fe4e)
3. コミット履歴の確認

   チェックアウトが完了すると、コミット履歴が最新から一つ前のコミットに戻っている事が確認できます。

   ![Visual Studio Codeで確認](/api/attachments.redirect?id=1c80aab7-07d2-4864-b8b6-bfd33dbcc6d5)
4. ファイルを確認

   ファイルを開いて中身を確認してみましょう。戻したコミットの内容になっている事が確認できます。

   ![ファイルの中身を確認](/api/attachments.redirect?id=7af1efb3-2f10-49c3-bb25-9a4f7fe35289)

:::

このように、コミット間を移動することができます。

### 最新のコミットに戻る

それでは次は、最新のコミットに戻してみましょう。

:::step
1. 最新のコミットに移動

   最新のコミットに戻る場合にはコマンドで次を実行します。

   *コマンド実行*

   ```bash
   git checkout master
   ```
2. コミット履歴の確認

   コミット履歴も最新のコミットに戻っている事が確認できます。

   ![Visual Studio Codeで確認](/api/attachments.redirect?id=021c5221-0f4d-4f12-ab39-f68fa3252b49)
3. ファイルを確認

   ファイルを開いて中身を確認してみましょう。最新のコミットの内容になっている事が確認できます。

   ![ファイルの中身を確認](/api/attachments.redirect?id=8b52ae39-6320-4d1e-8ce0-772bef0ffb31)

:::

このように、最新のコミットに戻すことができます。


:::syntax コマンドで過去のコミットに戻る
コマンドで過去のコミットに戻るには、次のコマンドを入力します。`<コミットハッシュ>`はコミットのハッシュ値（識別子）に置き換えてください。

*コマンド実行*

```bash
git checkout <コミットハッシュ>
```

:::


:::syntax コマンドで最新のコミットに戻る
コマンドで最新のコミットに戻るには、次のコマンドを入力します。

*コマンド実行*

```bash
git checkout master
```

:::

## リモートリポジトリをクローン

次にリモートにあるリポジトリを自分のPCにクローンします。


:::note クローンとは
クローンとは自分のPCにリモートリポジトリをダウンロードする事です。

:::

:::step
1. クローンするGitHubリポジトリページにアクセス

   クローンするGitHubリポジトリのWebページにアクセスします。今回は講師のリモートリポジトリで公開しているリポジトリをクローンします。ブラウザで次のURLにアクセスしてください。

   <https://github.com/imagepit/git-sample>

   ![GitHubリポジトリページ](/api/attachments.redirect?id=ab341313-ed5c-451c-99e5-ac79864fe049)
2. クローンURLをコピー

   下図のようにフォークしたリポジトリのWebページの「Code」部分をクリックしてクローンURLをコピーします。

   ![クローンURLをコピー](/api/attachments.redirect?id=f7b6a8bd-64ef-4ada-b829-4ca51e320dae)
3. workフォルダをVSCodeで開く

   VSCodeで「work」フォルダを開きます。

   ![workフォルダを開く](/api/attachments.redirect?id=5a75fd5f-54fe-410d-a425-efbb64981ba3)
4. クローンを実行

   VSCodeのターミナルで次のコマンドを入力してクローンを実行します。`<クローンURL>`は先程コピーしたクローンURLに置き換えてください。

   *コマンド実行*

   ```bash
   git clone <クローンURL>
   ```

   次のようにGitHubからリポジトリがクローンされ、`work`フォルダにリポジトリがダウンロードされます。

   ![](/api/attachments.redirect?id=c54307c7-29ee-4965-9cb2-5c902d91125c)
5. リポジトリのコミット履歴を確認

   VSCodeのSource Controlでリポジトリのコミット履歴を確認します。

   ![](/api/attachments.redirect?id=091152c0-295f-4184-9be8-50c2695135aa)

   このように、リモートリポジトリを自分のPCにクローンすることができます。

:::

クローンすることで、リモートリポジトリの内容を自分のPCにダウンロードできます。


:::note originとは
リモートリポジトリをクローンすると、リモートリポジトリの情報が「origin」という名前で登録されます。この「origin」はリモートリポジトリの情報を保持しているため、リモートリポジトリとのやり取りを行う際に使用します。ローカルリポジトリでは複数のリモートリポジトリを登録することができます。最初にクローンしたリモートリポジトリは「origin」という名前で登録されます。

:::


:::syntax コマンドでリモートリポジトリを解除する
リモートリポジトリを解除するには、次のコマンドを入力します。

```bash
git remote remove <リモートリポジトリ名>
```

:::

//clearpage

:::note GitHubは世界中のリポジトリが公開されている
GitHubは世界中の開発者が作成したリポジトリが公開されています。GitHubには多くのリポジトリが公開されているため、自分のPCにクローンして開発できます。

有名なGitHubリポジトリとしては、次のようなものがあります。

| リポジトリ名 | 説明  |
|--------|-----|
| torvalds/linux | オープンソースのオペレーティングシステム |
| nodejs/node | JavaScriptのランタイム環境 |
| facebook/react | JavaScriptのライブラリ |
| microsoft/vscode | オープンソースのコードエディタ |

:::

:::note コミットメッセージをわかりやすくするコツ
これまでいくつかコミットメッセージを入れてコミットしましたが、コミットメッセージはGitリポジトリを共有しているチーム内において大事なメッセージです。コミットメッセージはチームメンバーにとってわかりやすくする必要があります。メッセージの1行目に書いたメッセージはそのままコミット一覧に表示されますので、コミットのタイトルや概要を記述します。また一般的には2行目は空行とし、3行目から詳細を書くようにしましょう。

*コミットメッセージの書き方のルール*

```html
【1行目】コミットのタイトルや概要
【2行目】空行
【3行目】コミットの内容や詳細を記述する
```

*わかりやすいコミットメッセージの例*

```html
h1見出しデザインの追加

埋もれている見出しの視認性の向上のため
```

*わかりにくいコミットの例①*

```html
全体の変更
```

上記だけのコミットメッセージでは変更の内容が全然わかりません。

*わかりにくいコミットの例②*

```html
バージョンアップ
```

上記だけのコミットメッセージでは何をバージョンアップしたのか、何のためのバージョンアップなのかわかりません。

*わかりにくいコミットの例③*

```html
バグ修正
```

上記だけのコミットメッセージでは何のバグかがわかりません。**コミットメッセージはチーム開発では非常に大事なものととらえしっかりとわかりやすく書く癖をつけましょう。**

:::

## リモートリポジトリのプル・プッシュ

### プルとプッシュの概要

クローンしてリポジトリの変更をリモートリポジトリに反映してみましょう。ローカルリポジトリで行ってきた変更をリモートリポジトリに反映させることを「プッシュ」といいます。また、逆にリモートリポジトリの最新状態をローカルリポジトリに反映する作業を「プル」といいます。

 ![プッシュとプル](/api/attachments.redirect?id=82305428-cf02-401b-bc38-7a7f5a405399)

## ファイルをGit管理から外す

Gitでバージョン管理しているフォルダの中にあっても、バージョン管理が不要だったり、管理したくないファイルが出てくることがあります。そういったファイルをGitリポジトリから対象外として外してみます。

管理したくないファイルを対象外にすることによって、不要なファイルをコミットすることを防ぐことができます。対象外にするファイルを指定するには「`.gitignore`」という名前のファイルを作成します。

:::note なぜバージョン管理しないファイルがあるのか
バージョン管理しないファイルがある理由はいくつかあります。

* テキストファイルでなく、バイナリ（機械語になっている）ファイルの場合は、変更履歴がわからないので管理しない方が都合がいい場合がある
  * Javaの.classファイルなど
* プロジェクトのビルド時に自動生成されるファイル
  * Eclipseの.classpathや.projectなど
  * Mavenのtargetフォルダなど
* ローカル環境に依存するファイル
  * ローカルの設定ファイルなど

通常バージョン管理する必要のないファイルとして次のものがあげられます。自動生成される不要なファイルには次のようなものがあります。

| ファイル | 説明  |
|------|-----|
| `Thumbs.db` | Windowsの場合に生成されるサムネイルキャッシュファイル |
| `.DS_Store` | Macの場合に生成されるファイル |
| `.settings` | Eclipseの設定フォルダ |
| `.project` | Eclipseのプロジェクトフォルダ |
| `.classpath` | Eclipseの設定フォルダ |
| `build` | EclipseのJavaビルド用フォルダ |

通常、こういったファイルやフォルダをGit管理から外す設定を行います。

:::

### .gitignoreファイルの作成

バージョン管理しないファイルを指定するには「`.gitignore`」という名前のファイルを作成して、その中に除外したいファイルやフォルダを指定します。

このように`.gitignore`ファイルで指定したファイルはGit管理から除外されます。

//clearpage

:::note .gitignoreファイルの書き方
.gitignoreファイルは「`sample.log`」のように具体的なファイル名で指定できますが、ディレクトリごと除外したり、拡張子を指定して同一拡張子のファイルはすべて除外するなどといった指定もできます。

**.gitignoreの主な書式例**

| 書式  | 説明  |
|-----|-----|
| `#` | コメント（行頭に#を書くとコメントとして扱われる） |
| `!` | 指定したものを除外しない |
| `test.txt` | 指定したファイルを除外 |
| `/test.txt` | ルートディレクトリ直下にあるtest.txtを除外 |
| `testdir/` | testdirという名前のフォルダを除外 |
| `*.psd` | psdという拡張子をもつファイルをすべて除外 |

*.gitignoreの記述例*

```js
//addstart
# 拡張子が.logのものを除外する
*.log

# .logの拡張子でもtest.logは除外しない
!test.log

# sample.htmlというファイルを除外
sample.html

# ルートディレクトリにあるsampledirというディレクトリを除外
sampledir/

# dirという名前のディレクトリを除外
dir/
//addend
```

:::

このように、`.gitignore`ファイルを作成して、Git管理から外したいファイルやフォルダを指定できます。

## リモートリポジトリの削除

リモートリポジトリを削除する方法を確認します。

:::step
1. VSCodeでworkフォルダを開く

   VSCodeでworkフォルダを開きます。
2. ローカルリポジトリのリモートリポジトリの登録解除

   VSCodeのターミナルで次のコマンドを実行してリモートリポジトリの登録を解除します。

   *コマンド実行*

   ```bash
   cd git-sample
   git remote remove origin
   ```

   これで、リモートリポジトリの登録が解除されました。
3. リモートリポジトリの削除

   GitHubにアクセスしてリモートリポジトリを削除します。リポジトリページの「Settings」をクリックします。

   ![](/api/attachments.redirect?id=04d09582-81cb-4c36-b04b-2c7d45a36c01)
4. リポジトリの削除

   リポジトリの設定画面が表示されたら、一番下にスクロールして「Delete this repository」をクリックします。

   ![](/api/attachments.redirect?id=b0d8534b-9105-4be4-bbd4-6e7b74d23640)
5. リポジトリの削除確認

   リポジトリの削除確認画面が表示されたら「I want to delete this repository」をクリックします。

   ![](/api/attachments.redirect?id=a7b4999d-7ecd-4e30-a72a-02bdf2d6b73b){w=80}

   次の画面では「I have read and understand these effects」ボタンをクリックします。

   ![](/api/attachments.redirect?id=ed8e7df3-d013-432b-90fc-599465b0ec64){w=70}

   リポジトリの削除確認画面が表示されたら、リポジトリ名を入力して「Delete this repository」をクリックします。

   ![](/api/attachments.redirect?id=c4d6d3e1-f702-4f66-ba46-6ba2ae5b44ba){w=80}
6. リポジトリの削除完了

   リポジトリが削除されました。

   ![](/api/attachments.redirect?id=d8930f4c-7d9e-4a8d-94c6-9ae5bccdfcb9){w=70}

:::
