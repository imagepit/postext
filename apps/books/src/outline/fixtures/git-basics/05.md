## Gitを使ったチーム開発

実践に向けて実際にチームでGitを使っていきます。

### チームを作る

数人でチームを作ります。その中からチームリーダーを選任してください。

### リモートリポジトリの作成（チームリーダーのみ）

チームリーダーになった人はチーム専用のリモートリポジトリをGitHubに作ります。

:::step
1. リモートリポジトリの作成

   GitHubにログインして画面右の「+」ボタンをクリックして「New repository」をクリックします。

   ![](/api/attachments.redirect?id=646126bc-b14f-45f4-ba4c-6d6da8e68d88){w=60}

   「Repository name」に「git-team-test」入力し、また「Private」のラジオボタンをクリックして「Create repository」ボタンをクリックします。

   ![](/api/attachments.redirect?id=f15a9e86-3ce1-45a4-bfeb-02fb2423bf20){w=70}

   下図の画面が表示され空のリポジトリが作成されます。

   ![](/api/attachments.redirect?id=b8e512cb-053e-4afc-a872-cd7c223a0e61){w=70}

:::

### アプリの動作確認（チームリーダーのみ）

それではサーブレットを使ったJavaのアプリケーションがビルド・実行できるかどうか確認します。

:::step
1. サンプルプロジェクトのクローン

   次のコマンドを実行してサンプルプロジェクトをクローンします。

   *コマンド実行*

   ```bash
   cd Desktop/work
   git clone https://github.com/imagepit/java-ee-gradle.git java-sample
   ```
2. VSCodeでプロジェクトを開く

   VSCodeでプロジェクトを開きます。

   *コマンド実行*

   ```bash
   code java-sample
   ```
3. サーブレットの追加

   `src/main/java/com/example/servlet/`フォルダ直下に`HelloServlet.java`を作成してください。

   *src/main/java/com/example/servlet/HelloServlet.java*

   ```java
   package com.example.servlet;
   //addstart
   import java.io.IOException;
   import java.io.PrintWriter;
   import jakarta.servlet.ServletException;
   import jakarta.servlet.annotation.WebServlet;
   import jakarta.servlet.http.HttpServlet;
   import jakarta.servlet.http.HttpServletRequest;
   import jakarta.servlet.http.HttpServletResponse;
   
   @WebServlet("/hello")
   public class HelloServlet extends HttpServlet{
   	@Override
   	protected void doGet(HttpServletRequest req, HttpServletResponse resp) throws ServletException, IOException {
   		PrintWriter out = resp.getWriter();
   		out.print("Hello main page!!");
   	}
   }
   //addend
   ```
4. サーブレットの動作確認

   それではサーブレットを起動してWebアプリケーションが動作するか確認してください。次のコマンドを実行します。

   *コマンド実行*

   ```bash
   ./gradlew.bat clean appRun
   ```

   次のように出力されればサーブレットが動作しています。

   ![動作確認](/api/attachments.redirect?id=131eaa65-057c-48fc-926a-ab20479db73d)

   次のようにブラウザでアクセスしてサーブレットが動作していることを確認してください。

   http://localhost:8080/hello

   ![動作確認](/api/attachments.redirect?id=e4b50e63-151a-4c31-9494-622f4c80c300)

   アプリを停止するにはCtrl+Cを押し、「y」を入力してEnterキーを押してください。

   ![アプリ停止](/api/attachments.redirect?id=e8d7687f-8657-457e-855f-15b6cf41591e)

:::

### 初回コミット・プッシュ

それでは初回コミットを行います。

:::step
1. コミット

   次のコマンドを実行してコミットします。

   *コマンド実行*

   ```bash
   Remove-Item .git -Recurse -Force
   git init
   git add .
   git commit -m "初回コミット"
   ```
2. プッシュ

   次のコマンドを実行してプッシュします。`<リモートリポジトリのURL>`には先ほど作成したリモートリポジトリのURL（HTTPS）を指定してください。

   *コマンド実行*

   ```bash
   git remote add origin <リモートリポジトリのURL>
   git push origin main
   ```
3. リモートリポジトリの確認

   GitHubのリモートリポジトリの画面にアクセスしてください。リモートリポジトリに初回コミットした内容が表示されているはずです。

   ![リモートリポジトリの確認](/api/attachments.redirect?id=78b8de06-9c5c-4f11-85a1-4bdd409ea059)

:::

## ファイルのマージを理解する

チーム開発にてGitを使う上で重要となるのがマージです。これから実際にチームでマージを行い理解を深めていきます。

### マージとは

マージとはリモートリポジトリの最新情報を、自分のローカルリポジトリに取り込む作業の事です。 もしGitを使っていない場合、このマージ作業を手作業で行う事になりとても管理が大変です。 Gitを使う事によりマージを効率的に行う事ができます。

 ![マージの概要](/api/attachments.redirect?id=9224f7c3-1056-4d00-a4fa-e8b1a29d9ee6)

### マージが発生する状況

実際にマージが発生する状況を考えてましょう。 Gitをつかった共同作業では基本的にプルを行ったときにマージが行われます。

例えばAさんとBさんが同じリモートリポジトリを使って開発を行っていたとします。 Aさんがファイルを更新してコミット・プッシュします。 その後Bさんがファイルを更新してコミットしてプルを行うときにマージが発生します。

 ![マージが発生するケース](/api/attachments.redirect?id=bcb1b0d9-d048-46e6-ac94-43c0ef9ef8a0)

### マージ結果の種類

このようにローカルリポジトリの作業開始時点でのリモートリポジトリの状態からプルするまでの間に他のメンバーからリモートリポジトリへのプッシュが行われるとマージが発生します。 このマージ作業はGitが自動的に行ってくれます。実際のマージ処理では次の表のように4種類のマージ結果が詳細情報画面として出力されます。

\: マージ結果の種類

| 結果  | 内容  |
|-----|-----|
| Fast Forward | ローカルリポジトリの情報が古いだけで、リモートリポジトリでのみ変更がある場合はリモートリポジトリの内容をすべて正として取り込む |
| マージコミット | 両方（ローカルとリモート）リポジトリに差分（変更）があったが、その差分が異なる箇所（同じファイルの同じ箇所でない）だったのでマージを行い、それをコミットする |
| コンフリクト | 両方（ローカルとリモート）リポジトリに差分（変更）があって、その差分が同じ箇所にあったあので、どのようにマージすべきか確認が必要な状態 |

### Fast Forwardの確認

 ![Fast Forwad](/api/attachments.redirect?id=652e04b4-b766-4d56-9351-164716a9edb6)

チームの中で更新する人を1人（Aさん）を決めてください。Aさんは次のコードをプロジェクトに追加してください。

#### Aさんの作業

:::step
1. サーブレットの追加

   `src/main/java/com/example/servlet`に`SecondServlet.java`を作成して下記コードを追加してください。

   *src/main/java/com/example/servlet/SecondServlet.java*

   ```java
   package com.example.servlet;
   //addstart
   import java.io.IOException;
   import java.io.PrintWriter;

   import jakarta.servlet.annotation.WebServlet;
   import jakarta.servlet.http.HttpServlet;
   import jakarta.servlet.http.HttpServletRequest;
   import jakarta.servlet.http.HttpServletResponse;
   @WebServlet("/second")
   public class SecondServlet extends HttpServlet{
   	@Override
   	protected void doGet(HttpServletRequest req, HttpServletResponse resp) throws ServletException, IOException {
   		PrintWriter out = resp.getWriter();
   		out.print("Hello second page!!");
   	}
   }
   //addend
   ```
2. コミット・プッシュ

   コミット・プッシュしてください。

   *コマンド実行*

   ```bash
   git add .
   git commit -m "SecondServletを追加"

   ```

   GitGraphで確認してください。コミットが追加されていることを確認してください。

   ![](/api/attachments.redirect?id=a4d798a6-81fa-4979-83b8-7764b70c133e)

:::

#### Aさん以外の作業

:::step
1. プル

   プルしてください。

   *コマンド実行*


   この場合は単純にAさんの更新した差分を他のメンバーがプルして皆が同じ最新状態になります。

このようにFast-Forwardなマージは確実にマージされます。

### マージコミットの確認

これからマージコミットの確認を行います。マージコミットとはマージを行った時に自動的に作成されるコミットの事です。次のように複数のメンバーが更新してコミットを行い、後にマージを行ったメンバーがプルを行った時にマージコミットを行います。

 ![マージコミット](/api/attachments.redirect?id=8f6317e8-2747-44fa-afb1-10b1219bc4df)

チームの中で更新する人を1人（Aさん、Bさん）を決めてください。

#### Aさんの作業

:::step
1. HelloServlet.javaの修正

   HelloServlet.javaを修正してください。
   * サーブレットとしての出力内容をh1タグで囲う修正を加えています。

   *src/main/java/com/example/servlet/HelloServlet.java*

   ```java
   @WebServlet("/hello")
   public class HelloServlet extends HttpServlet{
     @Override
     protected void doGet(HttpServletRequest req, HttpServletResponse resp) throws ServletException, IOException {
       PrintWriter out = resp.getWriter();
       //delstart
       out.print("Hello main page!!");
       //delend
       //addstart
       out.print("<h1>Hello main page!!</h1>");
       //addend
     }
   }
   ```

   コミット・プッシュしてください。

   *コマンド実行*

   ```bash
   git add .
   git commit -m "HelloServletを修正"
   git push origin master
   ```

   GitGraphで確認してください。コミットが追加されていることを確認してください。

   ![](/api/attachments.redirect?id=932ad2cd-dc7e-496c-9805-95b0d8741c15)

:::

#### Bさんの作業

:::step
1. SecondServlet.javaの修正

   SecondServlet.javaを修正してください。
   * HelloServletと同様に出力内容をh1タグで囲っています。

   *src/main/java/com/example/servlet/SecondServlet.java*

   ```java
   @WebServlet("/second")
   public class SecondServlet extends HttpServlet{
     @Override
     protected void doGet(HttpServletRequest req, HttpServletResponse resp) throws ServletException, IOException {

       //delend
   ```

2. コミット

   Bさんはコミットしてください。

   *コマンド実行*

   ```bash

   git commit -m "SecondServletを修正"
   ```

:::caution git pullで警告が出る場合
今回のようにコミットが先に進んでいるリモートリポジトリをプルする場合には次の警告が出てしまいます。

*警告メッセージ*

```txt
warning: Pulling without specifying how to reconcile divergent branches is
discouraged. You can squelch this message by running one of the following
commands sometime before your next pull:

  git config pull.rebase false  # merge (the default strategy)
  git config pull.rebase true   # rebase
  git config pull.ff only       # fast-forward only

You can replace "git config" with "git config --global" to set a default
preference for all repositories. You can also pass --rebase, --no-rebase,
or --ff-only on the command line to override the configured default per
invocation.
```

この警告は次のようにMerge Commitせずにプルすることでマージさせることもできます。その場合にあらかじめ次の設定を行ってください。

*コマンド実行*

```bash
git config --global pull.rebase false
```

次のようにMerge Commitせずにプルすることでマージさせることもできます。

*コマンド実行*

```bash
git pull origin master
```

:::

### コンフリクトの解決

:::step
1. コンフリクトの解決（メンバー）

   コンフリクトを解決するために、両方の変更を活かした内容に編集します。`<<<<<<< HEAD`と`=======`の間には、リーダーの変更内容が含まれています。`=======`と`>>>>>>> origin/main`の間には、メンバーの変更内容が含まれています。コンフリクトにより追加された部分を削除して、以下のように編集します。

   *src/main/java/com/example/servlet/HelloServlet.java*

   ```java
   @WebServlet("/hello")
   public class HelloServlet extends HttpServlet{
     @Override
     protected void doGet(HttpServletRequest req, HttpServletResponse resp) throws ServletException, IOException {
       PrintWriter out = resp.getWriter();
       out.print("<h1>Hello main page!!</h1>");
       //addstart
       out.print("<p>メニュー</p>");
       out.print("<p>コンテンツ</p>");
       //addend
     }
   }
   ```
2. コミット

   Bさんはコミットしてください。

   *コマンド実行*

   ```bash
   git add .
   git commit -m "HelloServletを修正"
   ```
3. 更新をプッシュ

   *コマンド実行*

   ```bash
   git push origin master
   ```
4. 更新内容をプル

   Bさん以外はリモートリポジトリの内容をプルしておいてください。

   *コマンド実行*

   ```bash
   git pull origin master
   ```

   次のようにコンフリクトを解消したコミットが追加されます。

:::

このようにプルしてマージする場合にはFast-Forward、Auto Merge、Conflictが起こりえます。それを踏まえる事で効率的にチーム開発を行う事ができます。


:::caution コンフリクトしない状態を保つ
このようにチーム開発の進め方によっては頻繁にコンフリクトが起きてしまい、混乱を生じて効率が悪くなる可能性があります。コンフリクトをなるべく起きないようにするには下記の点を気をつけましょう。

* 出来る限り複数人で同じファイルを更新しない
  * 異なるファイルであればマージが発生してもConflictは起きない
  * 予め同じファイルを更新しないような作業分担を考える
  * 共通ファイルなどの修正をしたくなった場合はチームメンバーと声を掛け合いながら作業を行う
    * チームリーダーなどプロジェクト全体を把握してスキルの高い人がConflictを解決できるように進める
  * 複数の人が修正しなければいけないような巨大な一つのファイルを作らない
    * オブジェクト指向的にプログラムの責務毎にクラスを分けて開発する
* 一つの作業毎にコミット・プッシュする
  * 複数の作業をまとめてコミットするとファイルの修正範囲が広くなりConflictが発生しやすい
  * 一つの作業毎にしっかりコミットメッセージで説明を記述しながら小まめにコミット・プッシュする
* 出来る限りFast-Forwardな状態を保つ
  * Fast-Forwardであればマージは発生しない
  * 作業終了時は必ずコミットしてプッシュしておく
  * 作業開始時はプルしてから始める

:::
